# Автоматические тесты

Запускайте из корня проекта:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
```

Используется `unittest` из стандартной библиотеки Python: устанавливать новые
зависимости не нужно. Явное `-s tests` ограничивает поиск каталогом тестов;
старый демонстрационный `test_parser.py` в корне не запускается.

Перед каждым тестом `TemporaryDirectory` создаёт отдельный временный каталог.
`patch.object` временно заменяет `database.db.DB_PATH` на путь внутри него.
Тестовая функция из `legacy_schema.py` создаёт старую схему, а явная миграция
переводит этот временный файл в v1, затем отдельная v2 добавляет программы.
Миграция v3 добавляет архивирование и ревизии, v4 — необязательное число подходов.
`init_db()` только проверяет результат.
Переменные окружения, `.env`, локальная база разработки и серверная база
не изменяются. `addCleanup` восстанавливает путь и удаляет временные файлы
даже при падении проверки. Соединения закрываются через `finally`.

Тесты проверяют фактический путь соединения, пустую начальную базу и сохранение
тренировки с подходом. Они не запускают `main.py`, polling, планировщик или
Google Sheets. `import_workouts.py` теперь безопасен при импорте: запись разрешена
только при явном запуске административной команды.

Добавлены проверки миграции, изоляции двух пользователей, личных показателей и
настроек, запрета чужих workout_id, Google Sheets и офлайн-сценариев Dispatcher.
Тесты программ проверяют произвольное число дней, повторы упражнений, импорт A/B/C,
снимки, сохранение шага, восстановление FSM и откат v2 при ошибке.
Тесты редактора проходят создание двух дней, настройку подходов, поиск с русским
регистром и страницами, подтверждения, чужие ID, старые кнопки, архив и откат v3.
Этап 7 проверяет отсутствие фиктивных шаблонов, сохранение цикла и ID дней,
связи подходов с конкретным включением упражнения и перезапуск.
Тесты проверяют создание двух дней по три упражнения за 33 действия с карточками,
русский/английский поиск, синонимы, опечатки, изображения и возврат к результатам,
исправление
конкретного включения без продвижения шага, транзакционный откат, ревизии, перезапуск
и подтверждение /cancel. Старые callback отключённого прототипа остаются неактивными.
В тестах Telegram заменён подставным транспортом, Google — mocks. Не запускайте параллельные
потоки с разными подменами общего `db.DB_PATH` в одном процессе.
