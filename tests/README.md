# Автоматические тесты

Запуск из корня Project:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
git diff --check
```

Используется unittest стандартной библиотеки; новых зависимостей нет.
Параметр `-s tests` ограничивает поиск каталогом тестов; демонстрационный
`test_parser.py` в корне не входит в автоматический набор.

## Изоляция

Каждый тест создаёт отдельную SQLite-базу в TemporaryDirectory. patch.object
подменяет `database.db.DB_PATH`; тесты явно применяют миграции к этой временной
базе. Соединения закрываются, подмены и временные файлы удаляются через cleanup.
Реальная локальная/серверная БД, .env и секреты не изменяются.

Dispatcher-тесты используют MemoryStorage, SimpleEventIsolation и fake Telegram
transport. Они не запускают main.py, polling, планировщик или Google Sheets sync.
Google API заменён mocks; отдельная защита запрещает реальную авторизацию.
Параллельные тестовые процессы изолированы временными файлами; параллельные
потоки с разными подменами общего DB_PATH в одном процессе не поддерживаются.

## Проверяемые сценарии

- Миграции, их повторяемость и транзакционный откат, внешние ключи.
- Внутренний users.id и Telegram ID, изоляция владельцев, открытая/закрытая
  регистрация, доступ только из личных чатов, экспорт только владельца.
- Произвольные дни программ, цикл по идентичности дня, неизменяемые снимки,
  фактические подходы, очередь отложенных, автоматический переход и /resume.
- Автосохранение каждого подтверждённого изменения редактора; сохранность после
  закрытия и потери FSM; отсутствие пустых дней/фиктивных подходов; первая
  программа и явная активация следующих; ID повторных включений.
- Новые «Назад»/«Закрыть редактор», полный просмотр, кнопочная перестановка,
  подтверждения удаления последнего упражнения/дня, архив и удаление программ
  без потери истории, ошибки SQLite и конфликты revision.
- RU/EN поиск, ё/е, пробелы, синонимы, опечатки и ранжирование уточнения «с весом»;
  непрерывный повторный запрос после нулевых и ненулевых результатов.
- Полные русские подписи без сборки из переводов отдельных слов; карточки с
  двумя фазами изображения, одной и без картинки; ошибка отправки и возврат
  на ту же страницу поиска без изменения программы.
- Незавершённые legacy/пустые/snapshot тренировки, дата и часовой пояс,
  прошедшее время без выдуманной длительности, все подходы с ограничением
  длины сообщений и страницами.
- Удаление только после явного подтверждения; возврат без изменения данных;
  подставленные ID/токены, повторное нажатие, завершённая/удалённая/изменённая
  тренировка, изменение подходов legacy при прежнем числе строк.
- Завершение только с фактически записанными подходами; удаление не меняет
  программу, другие тренировки или курсор; возврат к выбору дня.
- Переключение тренировка → редактор → продолжение сохраняет снимок, очереди,
  введённый с ошибкой текст и режим исправления; старый callback редактора
  не приостанавливает уже продолженную тренировку.

Основные новые проверки находятся в test_unfinished_workout.py,
test_program_ux_integration.py и обновлённых test_editor.py/test_catalog_ux.py.
Старые UI-ожидания ручного сохранения заменены проверками фактического
автосохранения; проверки БД, изоляции и истории сохраняются.

Результаты последнего полного прогона и сценарий ручной проверки:
[PROGRAM_EDITOR_UX.md](../PROGRAM_EDITOR_UX.md).

## UX-hotfix истории и тренировки

Добавлены test_workout_ux_hotfix.py (23 Dispatcher-сценария),
test_workout_ux_database.py (10 проверок данных) и test_workout_presentation.py
(8 проверок отображения). Проверяются прямой запуск дня, история без служебного

результат по ID через все дни, границы включений, даты/числа и длинный HTML.
