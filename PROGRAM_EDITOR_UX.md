# Реализация интерфейса программ и незавершённых тренировок

Последующий hotfix истории и карточек тренировок: [WORKOUT_UX_HOTFIX.md](WORKOUT_UX_HOTFIX.md).

Работа выполнена в локальной ветке `feature/program-editor-ux` проекта Project.
Конструктор сохраняет подтверждённые изменения сразу в SQLite. Вход в программы
и тренировочные дни объединён через «🏋️ Тренировка». Любая незавершённая запись
получает карточку фактических данных, завершение с сохранением и подтверждаемое
удаление. Схема остаётся v4, новая миграция не нужна.

## Навигация с текстами кнопок

- «🏋️ Тренировка» → «Программа: … / Выберите тренировочный день.» →
  «Следующий день по порядку», кнопки дней, «Редактировать программу»,
  «Список программ». Выбор дня сразу начинает тренировку с первого упражнения.
- Если программ нет: «Создайте программу: добавьте тренировочные дни и упражнения.»
  и «Создать программу». A/B/C новым пользователям не назначаются.
- «Список программ» → личные программы с отметкой ✓ активной, «Создать программу»,
  «Архив», «Назад», «Закрыть редактор».
- Программа → дни, «Добавить день», «Просмотреть программу»,
  «Переименовать программу», «Изменить порядок дней» при нескольких днях,
  «Сделать активной» для неактивной, «В архив», «Удалить программу»,
  «Назад», «Закрыть редактор».
- День → упражнения, «Добавить упражнение», «Переименовать день»,
  «Изменить порядок» при нескольких упражнениях, «Удалить день», «Назад»,
  «Закрыть редактор».
- Упражнение в дне → «Моё название», «Удалить упражнение»,
  «Необязательный план», «Назад», «Закрыть редактор».
- Поиск → результаты и страницы; новый текст сразу запускает новый поиск.
  При нулевом результате предлагается «Введите другое название», без номера
  страницы и предложения выбирать отсутствующий результат.
- Карточка найденного упражнения → название, английское имя отдельно, мышцы,
  оборудование и доступные изображения; «Добавить в день»,
  «Назад к результатам», «Закрыть редактор».
- Перестановка → выбрать упражнение/день → выбрать номер позиции в сетке.
  Подтверждение и текстовый ввод номера не требуются.
- Подтверждения редактора → «Да» / «Назад»; «Закрыть редактор» доступен и здесь.
  При последнем упражнении подтверждается удаление вместе с днём; при последнем
  дне отдельно подтверждается удаление программы с сохранением истории.
- Архив → программа → «Восстановить», «Просмотреть программу»,
  «Удалить программу», «Назад», «Закрыть редактор».

«Назад» перемещает на предыдущий логический экран и сохраняет уже записанные
изменения. «Закрыть редактор» возвращает в раздел тренировок. Старые /programs,
«Мои программы» и «🗂 Мои программы» остаются совместимыми входами; отдельной
дублирующей кнопки в главном меню нет.

При незавершённой тренировке вход в раздел показывает её карточку. «Назад» из
карточки открывает обычный выбор дня с доступом к редактору и списку программ.
Начать ещё одну тренировку до завершения/удаления текущей нельзя. История
доступна независимо от наличия незавершённой записи.

## Два дня по три упражнения: 31 действие

Одно действие — одно нажатие кнопки или одна отправка текста. Условия: уже
имеется активная программа, поиск на первой странице, без ошибок и повторов
внутри дня. Число подтверждено Dispatcher-тестом test_simple_flows.py.

| Действия | Шаг |
| --- | --- |
| 1–4 | «🏋️ Тренировка» → «Список программ» → «Создать программу» → отправить название |
| 5 | Отправить название первого дня; сразу открыт поиск |
| 6–8 | Запрос первого упражнения → выбрать результат → «Добавить в день» |
| 9–12 | «Добавить упражнение» → запрос второго → результат → «Добавить в день» |
| 13–16 | Те же четыре действия для третьего упражнения |
| 17–19 | «Назад» к программе → «Добавить день» → название второго дня |
| 20–22 | Запрос первого упражнения второго дня → результат → «Добавить в день» |
| 23–26 | Четыре действия для второго упражнения |
| 27–30 | Четыре действия для третьего упражнения |
| 31 | «Закрыть редактор» |

Веса, повторения и число подходов не вводятся. Упражнения уже сохранены после
каждого добавления. Существующая активная программа сохраняет активность;
явная активация новой в эти 31 действие не входит. Первая программа пользователя
становится активной при первом непустом дне.

## Автосохранение, выход и перезапуск

Каждое подтверждённое изменение выполняется транзакционно с проверкой владельца
и expected_revision. Успешный экран строится после сохранения. ID оставшихся
дней и включений упражнений сохраняются, курсор выбирается по идентичности
следующего дня. Повтор упражнения после подтверждения получает отдельное включение.
Старые необязательные планы остаются в программе, фактических подходов из них
не создаётся.

Название новой программы и название нового дня до первого упражнения — временный
ввод. Первое добавление записывает сразу непустой день; выход до него не оставляет
пустых дней в БД. Уже добавленные дни/упражнения переживают закрытие редактора
и потерю MemoryStorage. Тесты проверяют восстановление из SQLite после очистки FSM.

Ошибка SQLite оставляет предыдущую корректную версию; интерфейс предлагает
«Повторить», «Открыть актуальную версию» и «Посмотреть мой ввод». Конфликт ревизии
не затирает актуальные данные. Неприменённый ввод сохраняется отдельно в FSM,
включая переход к списку или закрытие редактора. После перезапуска неподтверждённый
ввод и токены MemoryStorage исчезают; уже подтверждённые записи SQLite остаются.
Неотправленный текст Telegram боту недоступен.

При переключении тренировка → редактор сохраняется шаг, очередь и фактические
подходы SQLite, а отправленный с ошибкой текст и режим исправления временно
сохраняются в FSM. /resume или «Продолжить тренировку» возвращают к сохранённому
шагу. Если ревизия изменилась, старый текст явно обозначается как неприменённый
ввод прежнего упражнения. Редактирование/удаление программы не переписывает
снимок начатой тренировки.

## Незавершённая тренировка

Карточка показывает сохранённое название дня, достоверное название программы
из snapshot, дату/время в часовом поясе пользователя, «С начала прошло», число
упражнений с подходами и общее число подходов. Записанные подходы разделены
на разминку и рабочие; одинаковые последовательные подходы сжимаются с количеством.
Для пустой тренировки выводится «Подходы ещё не записаны». Для длинных списков
доступно «Посмотреть все подходы» со страницами, без потери записей.

Время с начала не обозначается фактической длительностью. Времена подходов
не выдумываются. У legacy без snapshot не угадываются программа, порядок и
положение упражнения; продолжение неизвестного шага не предлагается. Старое
время без offset трактуется по существующему соглашению как местное время
пользователя с явной пометкой в карточке. Некорректная дата обозначается неизвестной.

Действия: «Продолжить тренировку» только для проверенного восстанавливаемого
состояния, «Завершить с сохранением», «Удалить тренировку», «Назад».

«Удалить тренировку» → подтверждение с названием, датой и числом подходов →
«Да, удалить» / «Назад». До подтверждения нет удаления. Подтверждение привязано
к пользователю, выбранному workout_id и одноразовому токену. Внутри BEGIN
IMMEDIATE заново проверяются владелец, незавершённость и fingerprint всех
сохранённых полей, snapshot/progress/revision, подходов и связей включений.
Изменение веса при прежнем числе подходов тоже делает подтверждение устаревшим.
Завершённая/удалённая/изменённая запись, чужой ID/токен и повторное нажатие
не удаляют данные; интерфейс показывает актуальное состояние.

Удаление затрагивает только выбранную тренировку и связанные фактические
данные, очищает только её кеш, сохраняет программу, каталог, другие тренировки
и позицию цикла. «Назад» из подтверждения возвращает карточку с прежними данными.
«Завершить с сохранением» оставляет все существующие подходы и завершает запись,
не добавляя плановые и не помечая отсутствующие упражнения выполненными.
Оба успешных действия открывают обычный выбор дня. Завершение сохраняет прежнее
продвижение цикла, удаление его не продвигает.

## Каталог: фактическое покрытие и ограничения

Локальный каталог проверен через SQLite mode=ro, без записи:

- Всего 602 упражнения, 602/602 external_id покрыты словарём полных русских
  названий; в самой БД заполнен один корректный name_ru, он имеет приоритет.
- Для всех 602 подписей словаря нет смешения RU/EN, повторяющихся подписей
  или превышения лимита 120 символов. ID каталога не менялись.
- У 467 упражнений доступны два различных локальных изображения start/peak,
  у 134 — одно main, у одного — ни одного. Подписи: «Исходное положение»,
  «Пиковая фаза», нейтральное «Изображение упражнения» для main.
- HTTP/HTTPS изображений в локальном экземпляре нет. Используются только
  существующие ссылки/файлы выбранного упражнения. Доставка автоматически
  пытается показать до двух; ошибка оставляет рабочую текстовую карточку.
- «Назад к результатам» сохраняет запрос и страницу. Временные медиасообщения
  самого бота удаляются по сохранённым message_id при уходе с карточки;
  ошибка удаления обрабатывается без потери данных.

Контрольные запросы на реальном каталоге в режиме только чтения:
«брусья» → dips; «брусья с весом» → только weighted-dips;
«жим лежа» → bench-press первым; «бицепс со штангой» → barbell-curl первым;
«разведения в стороны» → lateral-raise первым.

Будущие неизвестные ID без корректного name_ru показывают целое английское имя,
а не приблизительный набор русских/английских слов. Серверный каталог отдельно
не проверялся. Нечёткий поиск предлагает варианты, а выбор упражнения остаётся
явным. Доступность внешних URL и наличие медиа на сервере зависят от окружения;
рабочая текстовая карточка сохраняется при ошибке доставки.

## Проверки

Исходный набор до изменений: 111 тестов, все прошли. Новые и обновлённые проверки
используют только временные SQLite, fake Telegram transport и mocks Google.
Полный итоговый прогон: 140 тестов за 34,351 секунды, все прошли; пропущенных
проверок нет. git diff --check — успешно. Новые сценарии включают 13 проверок
незавершённых тренировок, 4 сквозных проверки переключений и 6 API-проверок
каталога; обновлённые редактор/карточки/простые сценарии также входят в этот прогон.

Миграция не нужна: существующие workouts/workout_sets/workout_sessions и
таблицы программ обеспечивают хранение и защиту операций. Новых зависимостей нет.
Исторические миграторы и автоматическое применение схемы не изменялись.
После полного прогона SHA256 database/database.db и database/database-backup.db
совпадают с исходными: локальные базы не изменены. Серверная БД не открывалась.
Реальный Telegram-бот и Google Sheets sync не запускались; push/deploy не выполнялись.

## Ручная проверка после будущей публикации

1. В личном чате открыть «🏋️ Тренировка»: сразу видны активная программа и дни,
   рядом «Редактировать программу» / «Список программ».
2. Создать программу из двух дней по три упражнения по сценарию выше. Закрыть
   редактор, открыть снова: оба дня сохранены; подходов в истории не появилось.
3. В отдельном тестовом аккаунте без программ проверить создание первой и её
   автоматическую активацию; следующая программа не переключает активную.
4. Проверить RU/EN поиск, «жим лежа», «брусья с весом», опечатку и повторный
   текст после нулевого/ненулевого результата. Открыть карточки с двумя, одной
   и без картинки; вернуться на ту же страницу.
5. Переставить упражнение через «Изменить порядок» → номер позиции, затем
   проверить полный просмотр программы. Проверить «Назад» и «Закрыть редактор».
6. Начать тестовую тренировку, записать разминку и рабочие одним сообщением,
   отложить упражнение. Открыть редактор, изменить программу, вернуться через
   /resume: текущая тренировка продолжает прежний snapshot и очередь.
7. Открыть legacy и пустую незавершённую запись: проверить дату/зону, время
   с начала, количество и фактические подходы; у legacy нет ложной кнопки
   продолжения. Для длинной записи просмотреть все страницы подходов.
8. Нажать «Удалить тренировку», затем «Назад»: всё сохранено. Повторно открыть
   подтверждение и «Да, удалить»: только выбранная тестовая запись удалена,
   обычный выбор дня открыт, программа и следующий день цикла сохранены.
9. На отдельной тестовой записи выбрать «Завершить с сохранением»: прежние
   подходы появились в истории, невыполненные не созданы, открыт выбор дня.
10. Проверить историю: выбор дня сразу открывает последнюю завершённую
    тренировку этого дня; другие пользователи и их программы изолированы.

Разрушительные сценарии этой ручной проверки выполнять на предназначенных
для неё тестовых тренировках. Автоматический набор отдельно проверяет чужие ID,
устаревшие подтверждения, повторные нажатия и транзакционные конфликты.
