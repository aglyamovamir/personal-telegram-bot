# Каталог упражнений: поиск и карточка

Сценарий: название программы → название первого дня → «Добавить упражнение»
→ поиск → карточка → «Добавить в день». После добавления снова открыт день.
Задание подходов для создания программы не требуется. Новый текст на экране
результатов сразу выполняет новый поиск, в том числе после нулевого результата.

## Названия и поиск

Используются существующие таблицы `exercises`, `exercise_muscles`,
`exercise_images`. Записей в каталог и новых миграций нет.
`database/catalog_localization.py` содержит полные русские подписи и отдельные
поисковые синонимы, связанные с существующими `external_id`. Это метаданные
отображения: запись словаря не создаёт новое выбираемое упражнение, не меняет ID
и не объединяет варианты. Пользователь выбирает реальную строку из SQLite.

Корректное полное русское `name_ru` из БД имеет приоритет. Если его нет,
используется полная словарная подпись. Слова русского названия не собираются
заменой отдельных английских слов. Смешанная строка `name_ru` с английскими
словами либо строка с символом замены U+FFFD не используется. Для будущего ID,
не имеющего полной русской подписи, сохраняется целое английское название;
`has_russian_name=False` позволяет отличить этот случай. Английское исходное
название всегда доступно в `name_en` отдельно.

Поиск учитывает регистр, пробелы, ё/е, русские/английские названия, части слов,
синонимы и небольшие опечатки. Ранжирование: точные названия, точные синонимы,
начало названия, соответствие значимых слов, подстрока, нечёткое совпадение.
При одинаковом качестве порядок определяется названием и ID, поэтому
страницы стабильны. Предлоги не мешают поиску, формы названий оборудования и
«с весом» / «с дополнительным весом» нормализуются только для поиска.

Проверенные первые результаты:

| Запрос | ID |
| --- | --- |
| брусья | `dips` |
| брусья с весом | `weighted-dips` |
| брусья с дополнительным весом | `weighted-dips` |
| жим лежа / жим лжеа | `bench-press` |
| бицепс со штангой | `barbell-curl` |
| разведения в стороны | `lateral-raise` |
| жим гантелей лежа | `db-bench-press` |
| incline bench press | `incline-bench-press` |

Уточнение «брусья с весом» не заменяется обычными брусьями или гравитроном.
Подходящее упражнение не подставляется автоматически: карточка даёт проверить
русское название, оригинал, основные мышцы и оборудование перед добавлением.

## Изображения и API

`catalog.get_exercise(external_id)` возвращает `name`, `name_en`,
`has_russian_name`, `muscles`, `equipment_label` и список `images` длиной 0–2.
Каждый элемент `images` содержит:

- `source`: существующий локальный `Path` либо проверенный HTTP/HTTPS URL;
- `view`: значение фазы из каталога;
- `caption`: подпись, соответствующая этой фазе.

Для совместимости `image` содержит первый `source` либо `None`.
Сначала выбираются связанные `start` и `peak`, затем доступные `end`, `main`
или изображения с неизвестным видом; `image_url` служит резервным источником.
Один и тот же путь/URL не выдаётся дважды. Подписи: `start` — «Исходное
положение», `peak` — «Пиковая фаза», `end` — «Конечное положение», `main` и
неизвестный вид — «Изображение упражнения». Пиковая фаза не называется концом.

Карточка сразу отправляет до двух доступных изображений, без кнопки
«Показать изображение». Ошибка отправки оставляет рабочую текстовую карточку.
При переходах интерфейс старается убрать только свои предыдущие
медиасообщения; пользовательские сообщения не удаляются. При возврате
сохраняются запрос, страница, программа и текущий день.

Для локального пути проверяются наличие файла, расширение и принадлежность
`data/repdb`; выход за эту папку запрещён. У URL проверяются схема, адрес и
отсутствие встроенных учётных данных. Доступность внешнего сервера и доставка
через Telegram заранее не гарантируются. Картинки не скачиваются и не ищутся
во внешних каталогах.

## Проверенный локальный экземпляр

Проверка `database/database.db` выполнена соединением SQLite с `mode=ro`;
файлы в `data/repdb` только читались.

- Упражнений: 602. Словарных русских подписей: 602/602, отсутствующих и лишних
  ID относительно этой БД нет.
- В самой БД заполнено одно корректное `name_ru`:
  `plate-loaded-abdominal-crunch` — «Скручивания на тренажёре с блинами».
  Остальные 601 запись получают подпись из словаря без изменения БД.
- В `exercise_images`: 467 `start`, 467 `peak`, 134 `main`.
- У 467 упражнений реально доступны две разные локальные картинки, у 134 —
  одна, у одного — ни одной (`plate-loaded-abdominal-crunch`).
- Непустой `image_url` есть у 467 упражнений. Внешних HTTP/HTTPS URL не найдено.
- Для всех используемых значений основных мышц и оборудования есть подписи
  в `LABELS`. Если оборудование в исходных данных отсутствует, показано
  «Не указано».

Словарь составлен по английским названиям и описаниям существующих записей;
он не меняет исходные данные и технику упражнения. Для новых серверных
упражнений вне этих 602 ID потребуется добавить полную русскую подпись.
Состав серверного каталога и наличие файлов на сервере отдельно не проверялись.
Нечёткое совпадение остаётся поисковой подсказкой, поэтому выбор подтверждает
пользователь. Синонимы и нормализация не заменяют полную морфологическую модель.

Автоматические проверки: `tests/test_catalog_search.py` (контракт каталога,
ранжирование, языки, повреждённые подписи, только чтение, страницы, 2/1/0
изображений, фазы, дубли, пути и URL) и `tests/test_catalog_ux.py` (переходы,
повторный поиск, автоматическая доставка и ошибки Telegram на fake transport).
