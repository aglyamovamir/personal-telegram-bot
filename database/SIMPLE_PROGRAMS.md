# Программа задаёт дни и упражнения, фактические подходы записываются на тренировке

Упрощённый конструктор сохранён. По следующему явному запросу исправление
результатов реализовано на существующих связях, а /cancel стал безопасным:
актуальное описание — [WORKOUT_ACTIONS.md](WORKOUT_ACTIONS.md).

## Обновление схемы

Текущий код требует v4. Миграции v1–v3 не изменены и не запускаются автоматически.
`migrations_v4.py` явно перестраивает только program_day_exercises, чтобы
working_sets мог быть NULL. Все значения и ID старых включений и шаблонов,
дополнительные столбцы, пользовательские индексы/триггеры и счётчик ID сохраняются.
Исторические workouts, workout_sets и JSON-снимки не обновляются.

Для перестройки родительской таблицы FK временно выключены только у мигратора
до BEGIN IMMEDIATE. foreign_key_check и integrity_check выполняются до и после;
любая ошибка откатывает и данные, и DDL. Все рабочие соединения продолжают
использовать foreign_keys=ON. Незнакомое объявление старого ограничения вызывает
отказ и требует проверки схемы. Повтор v4 на готовой v4 ничего не меняет.

Сначала получить согласованную резервную копию серверной БД, сделать отдельную
тестовую копию и явно подготовить её предыдущими миграциями. Для копии со схемой v3:

```powershell
.\.venv\Scripts\python.exe -B -m database.migrations_v4 --database "C:\migration-tests\history-copy.sqlite3" --confirm-offline-copy
```

Эта команда не выполнялась над реальными базами. Мигратор не делает резервную
копию сам. При старой схеме запуск приложения отказывается продолжать работу.

## Программы без подходов

Минимальное упражнение в документе программы: `{"exercise_id": "bench-press"}`.
Имя берётся из каталога, своё имя необязательно. Нет working_sets — в БД NULL;
нет разминочных/рабочих шаблонов — в program_set_templates нет строк для этого
включения. NULL означает «план не задан», а не ноль выполненных подходов.

Новые упражнения конструктора больше не получают три фиктивных рабочих шаблона.
Для создания достаточно названия программы, непустых дней и упорядоченных
упражнений. После выбора упражнения сразу показывается список текущего дня;
можно снова нажать «＋ Найти упражнение». Карточка настроек автоматически не
открывается. Старые настройки доступны только при явном открытии упражнения
через отдельную кнопку «Необязательный план», поэтому
сохранённые ранее программы с весами, разминкой и working_sets продолжают работать.
Старый перенос A/B/C сохраняет прежние шаблоны и выполняется только явно владельцем.

## Политика цикла при редактировании

Редактор передаёт ID уже существующих дней. update_program проверяет, что каждый
такой ID принадлежит этой программе и встречается один раз. Их ID сохраняются
при переименовании, перестановке и изменении упражнений. Дни без ID создаются;
пропущенные существующие дни удаляются, без удаления истории тренировок.

Курсор выбирается по старому следующему day_id, а не сохраняется как голое число:

1. Следующий день остался — выбирается он, даже если поменял позицию/название.
2. Он удалён — выбирается первый оставшийся преемник в прежнем круговом порядке.
3. Ни одного прежнего дня не осталось — выбирается первый новый день.
4. При удалении дня уже начатой тренировки её снимок остаётся прежним; ссылка
   на источник становится NULL. Завершение этой тренировки не перезаписывает
   курсор, выбранный редактированием.

API-клиент должен передавать существующие IDs, чтобы сохранить идентичность дней.
Если прислать полностью новый список без IDs, это сознательная замена дней.
Одно переименование программы курсор не меняет. Недели и частота не участвуют.

## Фактическая запись и подготовка будущего исправления

Синтаксис workouts/parser.py не менялся. Сообщение содержит ВСЕ фактические
подходы текущего упражнения. После сохранения бот автоматически переходит дальше,
никаких обязательных «Сохранить», «Подтвердить» или «Продолжить» нет.
Карточка показывает выполненные/общие упражнения, очередь отложенных, инструкцию
и прошлые результаты. Число рабочих/разминочных подходов не предписывается даже
старым планом: в карточке только инструкция записи факта. Старые шаблоны остаются
в документе и снимках, для совместимости их можно отдельно просмотреть.

workout_set_occurrences сохраняет для каждого фактического set_id пару
(workout_id, exercise_position). Повтор одного каталожного упражнения внутри дня
имеет отдельную позицию снимка, поэтому его результаты не смешиваются.
get_occurrence_sets(user_id, workout_id, position) проверяет владельца и позицию,
затем только читает реальные строки конкретного включения. API замены/удаления
результатов включения добавлен следующим этапом с проверкой владельца/ревизии;
см. WORKOUT_ACTIONS.md. Старые кнопки отключённого прототипа отклоняются без изменений.
/resume продолжает восстанавливать текущий шаг из SQLite.

## Неоднозначности прежнего парсера — поведение не менялось

- Без внутренней пустой строки все подходы считаются рабочими.
- До единственной внутренней пустой строки — разминка (по два числа), после —
  рабочие. Три числа означают повтор рабочих подходов, а не отдельное поле веса.
- Пустые строки в начале/конце удаляются: завершающая пустая строка не делает
  предыдущие строки разминкой. Записать только разминку этим форматом нельзя.
- Парсер поддерживает x/× и «по», десятичную запятую. Его прежняя проверка самих
  числовых значений слабее проверки планов: дробные повторения и специальные
  float-значения не получили в этом этапе новой трактовки. Это отдельная задача
  валидации, а не молчаливое изменение синтаксиса.

## Создание двух дней по три упражнения: 27 действий

1–3: «Мои программы» → «＋ Создать программу» → отправить название.
4–5: «＋ Добавить день» → название первого дня.
6–14: три раза «＋ Найти упражнение» → запрос → выбор результата.
15: «Назад» к программе.
16–17: «＋ Добавить день» → название второго дня.
18–26: три раза «＋ Найти упражнение» → запрос → выбор результата.
27: «Сохранить программу» из второго дня.

Подсчёт подтверждён Dispatcher-тестом. Нажатие кнопки или отправка сообщения —
одно действие. Условия: результаты на первой странице, без ошибок и повторов
внутри одного дня. Дополнительная страница/подтверждение дубликата добавляют действие.
Выбор активной программы, если уже есть другая активная, добавляет одно действие.
Ни одного поля подходов заполнять не нужно; сохранение не создаёт workout_sets.

## Ограничения

- Исправление предыдущего включения активной тренировки доступно; редактор истории не добавлен.
- Старые тренировки без достоверного снимка/связей включений не угадываются.
- Общий черновик программы по-прежнему находится в MemoryStorage до сохранения.
- /cancel запрашивает подтверждение удаления; в режиме исправления отменяет только исправление.
- Sheets отправляет только завершённые тренировки. Главное меню не менялось.
