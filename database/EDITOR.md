# Telegram-конструктор программ: этап 5

В этапе 7 создание упрощено: подходы необязательны, текущая схема v4,
позиция цикла при правках сохраняется. Подробнее: [SIMPLE_PROGRAMS.md](SIMPLE_PROGRAMS.md).

## Экраны и сохранение

Главное меню → «🗂 Мои программы» (или /programs) → список с отметкой ✓ активной
программы. Здесь доступны создание, открытие и архив. В программе — дни,
переименование, просмотр состава, сохранение, выбор активной и архивирование.
В дне — поиск упражнений, переименование, перестановка и удаление дня.
В упражнении — рабочие и разминочные подходы, своё название, порядок и удаление.
Все списки программ, дней, упражнений и результатов поиска имеют страницы.

Редактор работает с черновиком в MemoryStorage. Нажатия меняют черновик, а
«Сохранить» записывает весь план одной транзакцией через существующий API
programs.py. Пустую программу, пустой день или неверные подходы сохранить нельзя.
Первое сохранение программы делает её активной только если другой активной нет.
Новому пользователю не копируется A/B/C.

«Назад» перемещает между экранами. «Отмена» при вводе отменяет только этот ввод.
Выход из изменённого черновика и /cancel требуют подтверждения его отбрасывания.
Удаление дня/упражнения требует подтверждения и применяется к БД лишь после
сохранения. Повтор упражнения разрешён, но повторное добавление просит подтверждение.

После сохранения можно открыть «Тренировка» прямо из главного меню: чистый
редактор закроется. Пока черновик изменён, нужно сохранить или отменить его.
При активной тренировке редактор недоступен, включая состояние после перезапуска,
когда тренировка есть в SQLite, но её FSM ещё не восстановлен. Опросы также
не перезаписывают FSM редактора.

## Архив и миграция v3

В programs добавлены только `archived_at` (nullable TEXT) и `revision`
(INTEGER NOT NULL DEFAULT 0). Архивирование выключает активность, но не удаляет
программу, дни, упражнения, снимки или историю. Архив можно открыть и восстановить;
после восстановления активную программу выбирают явно. Последняя доступная
программа архивируется только после отдельного предупреждения и подтверждения.
Старый административный delete_program сохраняется, но кнопки физического удаления
программы в Telegram нет.

Изменения схемы не выполняются на старте. Текущий код требует готовую v3.
Сначала получить согласованную резервную копию, создать отдельный тестовый
экземпляр и подготовить его предыдущими явными миграциями. Для копии со схемой v2:

```powershell
.\.venv\Scripts\python.exe -B -m database.migrations_v3 --database "C:\migration-tests\history-copy.sqlite3" --confirm-offline-copy
```

Команда не выполнялась на реальных базах. Мигратор требует существующий файл,
проверяет FK/целостность, выполняется транзакционно, откатывает DDL при ошибке,
повторный запуск на v3 ничего не меняет. Миграторы v1/v2 не изменялись.
Репетиция на актуальной серверной копии нужна до будущего рабочего перехода.

## Безопасность

- В callback только короткий токен экрана и индекс действия. Названия, поисковые
  запросы и произвольные внешние IDs не упаковываются в callback_data. Лимит 64 байта
  проверяется при построении клавиатуры.
- Действия хранятся в FSM конкретного пользователя. Каждый экран меняет токен;
  старое/чужое нажатие отклоняется. Перед записью токен потребляется однократно.
- SQL API заново проверяет владельца по внутреннему users.id. Открыть, изменить,
  архивировать или восстановить чужую программу по подставленному ID нельзя.
- При открытии запоминается revision. Сохранение с expected_revision выполняется
  в той же транзакции, что и проверка; устаревший черновик не затирает новые данные.
  При конфликте показывается сообщение и список программ: нужно открыть заново.
- Поиск использует существующие name_ru/name_en и Unicode casefold, поэтому
  русский регистр работает даже без SQLite ICU. Запрос параметризован, символы
  SQL и LIKE не превращаются в команды или шаблоны.
- Плановые подходы используют только program_set_templates. workout_sets
  заполняется исключительно фактическим вводом тренировки.
- Новые тренировки не запускаются из архивных программ. Уже начатый снимок
  остаётся прежним даже при изменениях через административный API.

## Формат настройки подходов

Рабочие или разминочные: каждая строка `вес повторения [количество]`.
Например, `50 8 3` — три плановых подхода; `20 10` — один.
Знак `-` вместо отдельного числа означает незаданное значение: `- 10 3`.
Для полного отсутствия разминки отправить отдельный `-`.
Необязательное число рабочих подходов можно менять отдельной кнопкой: новые шаблоны остаются
без веса/повторений. Рабочий план должен содержать хотя бы один подход.
Принимаются десятичные веса с точкой/запятой и символы x/×. Не принимаются
NaN/Infinity, неположительные повторения/количество, более 100 подходов в одном
разделе. Название — до 120 символов, запрос поиска — 2–100 символов.

## Сценарий: программа из двух дней

1. «Мои программы» → «Создать программу» → ввести «Мой план».
2. «Добавить день» → «Верх» → «Найти упражнение» → ввести «жим» или Bench.
3. Выбрать найденное упражнение. «Вес и повторения рабочих» → `50 8 3`.
4. «Разминочные подходы» → две строки `20 10` и `40 5`.
5. «Назад» до программы → «Добавить день» → «Низ».
6. Найти и выбрать присед, задать рабочие подходы, например `60 8 3`, разминку.
7. Вернуться к программе → «Просмотр состава» → «Назад» → «Сохранить».
8. «Сделать активной», если нужно переключиться с другой программы.
9. Главное меню → «Тренировка» → выбрать день или «Следующий день по порядку».
   Проверить состав → «Начать тренировку». Ввести фактически выполненные подходы.

## Ограничения текущего этапа

- Несохранённый черновик исчезает при перезапуске, как и другой незавершённый ввод
  в MemoryStorage. Сохранённые программы и прогресс тренировок остаются в SQLite.
- С v4 update_program сохраняет ID переданных существующих дней и следует за
  следующим днём по его идентичности. При удалении выбирается прежний оставшийся
  преемник. Полная замена дней без ID начинает новый список с первого дня.
- Редактирование одновременно с тренировкой в Telegram намеренно не поддерживается.
- Настройка плана не даёт рекомендаций: пользователь сам выбирает веса и подходы.
- Для одного пользователя допустим только один открытый черновик/экран редактора;
  старые сообщения имеют неактивные кнопки. Для восстановления экрана открыть
  «Мои программы»; изменённый черновик будет показан снова, если FSM сохранился.
- Общие ограничения проекта сохраняются: singleton и синхронный Sheets без очереди.
