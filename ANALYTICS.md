# Аналитика тренировок

Реализовано в ветке `feature/workout-analytics`. Миграция не требуется:
используется существующая схема v4. Реальные БД не изменялись.

## Навигация

Главное меню: «📊 Аналитика» вместо «📊 Сегодня».
`/analytics` — основной вход, `/today` и старая кнопка «Сегодня» — совместимые
входы в тот же экран. При старой reply-клавиатуре вызовите `/start`.

- «Разбор последней тренировки» → выбор дня → сравнение двух последних
  завершённых тренировок этого дня. Кнопки под разбором ровно две:
  «График тренировок …» и «Назад» (к выбору дня).
- «Прогресс по тренировкам» → выбор дня → график объёма и сводка.
- «Прогресс по упражнениям» → упражнения из собственной фактической истории,
  страницы и поиск → сначала график веса, затем график объёма, сводка.
  «Все подходы» открывает фактические записи по датам с границами включений.
- Периоды: «3 месяца», «6 месяцев», «Вся история». По умолчанию вся история.
- «Главное меню» возвращает основную клавиатуру.

После успешного завершения (включая `/exit` и завершение старой записи)
автоматически отправляется один PNG-график объёма соответствующего дня,
краткое сравнение и кнопка «Подробный разбор». Если подпись длинная, она
отправляется текстом после изображения с безопасным разбиением HTML.
При удалении тренировки отчёт не создаётся. Сбой отрисовки или отправки
картинки не отменяет сохранённые данные: используется текстовый отчёт.

## Правила расчётов

Источник — только завершённые тренировки текущего `users.id` и реальные
`workout_sets`. Шаблоны программы и разминка не включаются.

- Объём: сумма введённого веса × повторения рабочих подходов.
- Гантели: вес одной гантели, без автоматического удвоения.
- Дополнительное отягощение: без прибавления массы тела. Нулевой вес
  не означает отсутствие работы: подходы и повторения сохраняются в сводке.
- Вес на графике: максимум рабочих подходов за тренировку. Рядом в сводке
  показаны повторения всех подходов на максимальном весе, не только лучшего.
- Одна тренировка — одна точка. Несколько включений упражнения входят в
  её общий объём; в разборе и списке подходов включения разделены.
- Никаких утверждений о проценте роста силы или причин ухудшения.
- Изменение состава дня отмечается отдельно; общие объёмы разных дней
  не смешиваются в одну линию.
- Для начального нулевого объёма процент не вычисляется.
- Неконечные/отрицательные веса и неположительные повторения исключаются
  с предупреждением; исходные записи не исправляются и не удаляются.

Дни группируются по идентичности, как в разделе «История», включая старые
A/B/C владельца. Одинаковые имена разных программ не объединяются.
Упражнения ищутся по `exercise_id` среди всех дней одного пользователя.
Старые факты без ID учитываются в объёме дня, но не сопоставляются с
каталогом по приблизительному имени. Они доступны в обычной истории.

## Даты и большие истории

Сравнения используют разобранное время начала и ID при равенстве дат.
Учитывается timezone пользователя; старые naive даты трактуются как местное
время по существующему соглашению. Без достоверной даты запись не рисуется
на временном графике и не попадает в фильтр последних месяцев; во всей
истории и числовых итогах она сохраняется с пояснением.

Фильтры месяцев используют календарную дату, а не условные 90/180 дней.
Все точки периода учитываются, даже когда подписана только часть дат оси.
Списки дней/упражнений постраничные, список подходов — по тренировкам.

## Технические изменения

- `database/analytics.py`: чтение и расчёты с проверками владельца.
- `workouts/analytics_presentation.py`: фактические сравнения и пояснения.
- `workouts/charts.py`: PNG в памяти через matplotlib/Agg, без GUI; отрисовка
  вынесена из event loop, доступ к matplotlib сериализован.
- `keyboards/analytics.py`, `handlers/analytics.py`: меню и обработчики.
- `handlers/start.py`: совместимые входы и отчёт после commit завершения.
- `handlers/today.py`: совместимый вход `/today`.
- `main.py`, `access.py`, `keyboards/main_menu.py`: подключение раздела.
- `requirements.txt`: `matplotlib>=3.10,<4`.

Открытие аналитики и графиков не меняет FSM тренировки/редактора. Текстовый
поиск в аналитике начинается только при отсутствии другого ввода; из активной
тренировки доступны списки и графики без переключения её состояния.
Сохранение тренировок и экспорт Google Sheets остаются отдельными от аналитики.
Никаких API ИИ, ключей, платных запросов и новых фоновых заданий нет.

## Ручная проверка после будущей публикации

1. `/start` → «📊 Аналитика»: три раздела и возврат в главное меню.
2. Разбор A/B/C: фактические подходы, сравнение с тем же днём, две кнопки.
3. Прогресс дня: график, 3/6 месяцев/вся история; другой пользователь видит своё.
4. Прогресс упражнения: вес выше объёма, верные подписи гантелей/отягощения,
   повторения максимального веса и «Все подходы».
5. Открыть аналитику во время записи тренировки и затем продолжить ввод:
   позиция и отложенные упражнения не должны измениться.
6. Завершить тренировку: график и краткий итог появляются автоматически;
   «Подробный разбор» открывает тот же сохранённый результат.
7. Удалить тестовую незавершённую тренировку через подтверждение:
   аналитического отчёта после удаления нет.

Ограничения: веса разных тренажёров/техник сами по себе несопоставимы;
вес тела и число одновременно используемых гантелей не выводятся по догадке.
Отчёт не диагностирует усталость или причины застоя. Аналитика дневных
показателей и ИИ-комментарии отложены на отдельное согласование.

Проверки: весь набор — 205 тестов успешно; `pip check` — без нарушений,
`git diff --check` — без замечаний. PNG с двумя графиками дополнительно
отрисован и визуально проверен на условных данных, без чтения реальной БД.
