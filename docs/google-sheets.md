# Экспорт тренировок в Google Sheets

Экспорт включается переменной `GOOGLE_SHEETS_OWNER_TELEGRAM_ID`, совпадающей
с Telegram ID первоначального владельца из миграции v1. Остальные пользователи
продолжают работать со своими данными в SQLite без доступа к общей таблице.
Перед чтением подходов проверяется принадлежность тренировки внутреннему
`users.id`. Service account должен иметь права редактора целевой таблицы.
Ключ берётся из `GOOGLE_CREDENTIALS_B64` или локальной папки `credentials/`;
оба варианта содержат секрет и не должны попадать в Git.

## Значения и форматы

Используется gspread 6 (`>=6.2,<7`), проверенная локальная версия — 6.2.1.
Числа передаются Python-типами `int`/`float` с `value_input_option="RAW"`.
Смена формата ячейки сама по себе не преобразует ранее сохранённый текст.
Повторный экспорт переписывает строки выбранной тренировки и её подходов
числовыми значениями, включая даты.

| Лист | Столбцы | Формат |
| --- | --- | --- |
| Workouts | A: workout_id; F–H: минуты, все/рабочие подходы | NUMBER `0` |
| Workouts | B: дата | DATE `yyyy-mm-dd` |
| Workouts | E: начало | DATE_TIME `dd.MM.yyyy hh:mm:ss` |
| Workouts | I: рабочий объём | NUMBER `0.##` |
| Sets | A: workout_id; F–H: set_id, номер, признак разминки; J: повторения | NUMBER `0` |
| Sets | B: дата | DATE `yyyy-mm-dd` |
| Sets | I: вес; K: объём подхода | NUMBER `0.##` |

Дата и время передаются серийными числами Sheets от 1899-12-30. Начало
приводится к часовому поясу пользователя. Для старых значений без смещения
используется этот же часовой пояс. Длительность считается по реальным
моментам начала и конца, включая переходы летнего времени. Суточная отметка
о тренировке обновляется на ту же локальную дату.

## Повторная синхронизация

Идентификаторы читаются без форматирования Sheets; поддерживаются и старые
текстовые целые значения с точкой или запятой. Workouts обновляется по
`workout_id`, Sets — по `workout_id + set_id`. Старые строки без `set_id`
сопоставляются по упражнению и номеру подхода, используются по одной и
получают актуальный `set_id`. Для упражнения без каталожного ID используется
его сохранённое название. Чужие тренировки и посторонние строки не меняются.

Повторный вызов и повтор после потери ответа на append не добавляют уже
сохранённые строки. Вызовы сериализуются внутри одного процесса, что
соответствует текущему запуску `python main.py` и `singleton: true` на Amvera.
Для нескольких независимых процессов нужен отдельный механизм координации.
Ранее созданные дубликаты и отсутствующие в SQLite строки автоматически
не удаляются; завершённые тренировки приложение изменять не позволяет.

Сбой Google не отменяет сохранение в SQLite. Автоматической очереди повторов
нет: для исправления старых значений нужен повторный `sync_workout` владельца
для соответствующих тренировок. Этот обзор не запускает массовую выгрузку.

## Проверка

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_google_sheets.py" -v
```

Проверки используют настоящий `gspread.Worksheet` и подставной HTTPClient:
проверяют типы и форматы запросов, повторную выгрузку старых строк, потерю
ответа после append, два параллельных вызова, старые даты без смещения,
полночь UTC и переход летнего времени. Сетевые обращения запрещены тестами.
Дополнительные проверки владельца и изоляции находятся в `test_multiuser.py`.
Это локальная проверка совместимости API; доступ service account к рабочей
таблице и серверные переменные требуют отдельной проверки на Amvera.
