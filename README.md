# Telegram-бот тренировок

Python, aiogram 3, SQLite, Google Sheets; развёртывание на Amvera.
Личные программы, история и показатели пользователей изолированы.

## Где что находится

| Путь | Назначение |
| --- | --- |
| `main.py`, `access.py`, `scheduler.py` | Запуск, доступ, уведомления |
| `handlers/`, `keyboards/`, `states/` | Telegram-интерфейс и FSM |
| `database/` | SQLite API, явные миграции и импорт A/B/C |
| `workouts/` | Парсеры, отображение, графики и исходная A/B/C для переноса |
| `data/repdb/` | Общий каталог и изображения; используются ботом |
| `tests/` | Автоматические проверки на временных БД |
| `docs/` | Руководства и отдельно исторические отчёты |

Начать с [навигатора документации](docs/README.md).
Программы: [руководство](docs/database/EDITOR.md).
Аналитика: [расчёты и навигация](docs/analytics.md).
Миграции: [порядок и ограничения](docs/database/MIGRATIONS.md).

## Настройки и локальная проверка

Имена переменных описаны в [.env.example](.env.example).
Локальные значения задаются в `.env`, серверные — в настройках Amvera.
Не добавляйте токены, credentials или базы в Git.

- `DB_PATH`: локальный и серверный файлы независимы; на Amvera обычно
  `/data/database.db`. Различие путей нормально, автоматической синхронизации нет.
- `OPEN_REGISTRATION=true`: доступ к регистрации в личном чате без allowlist.
  При `false` используется `ALLOWED_TELEGRAM_IDS`.
- `GOOGLE_SHEETS_OWNER_TELEGRAM_ID`: экспорт только первоначальному владельцу.

Из корня проекта с установленными зависимостями из `requirements.txt`:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
git diff --check
```

Тесты не используют рабочие базы и реальный Telegram/Google Sheets.
Подробности: [tests/README.md](tests/README.md).

## Административные скрипты — не мусор

- `database/migrations.py`, `migrations_v2.py`, `migrations_v3.py`,
  `migrations_v4.py` — исторические версии миграций. Сохраняются и запускаются
  явно на подготовленной копии, не автоматически при старте.
- `database/import_legacy_program.py` и `workouts/program.py` — явный перенос
  первоначальной A/B/C владельцу старой истории, не регистрация новых пользователей.
- `import_workouts.py` — отдельный исторический импорт с явным путём и владельцем.
- `import_exercises.py` — административная загрузка исходного каталога;
  содержит путь `/data/database.db`, не запускайте его случайно локально.

## Что не удалять при очистке

`.env`, `credentials/`, SQLite-файлы и резервные копии — локальные данные,
исключённые из Git. `.venv/` — рабочее окружение; `.git/` — история проекта.
Изображения `data/repdb/images/` нужны карточкам упражнений.

Исторические отчёты лежат в `docs/history/`: их описания относятся к конкретным
этапам, а не обязательно к текущему интерфейсу. Опубликованный код не меняется
от локальной очистки: push/deploy выполняются отдельно.
