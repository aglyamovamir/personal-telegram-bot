# Многопользовательский режим: этап 3

Этап 4 добавил персональные программы и восстановление прогресса тренировки.
Текущий код этапа 7 требует v4; команды и изменения: [database/SIMPLE_PROGRAMS.md](database/SIMPLE_PROGRAMS.md).

## Перед будущим запуском

Этот этап не применяет миграцию к реальным данным. Код требует готовую схему v2.
Сначала сделать согласованную резервную копию серверной SQLite, проверить явную
миграцию на её отдельной копии по `database/MIGRATIONS.md`. Для рабочего перехода
позже потребуется согласованно остановить старый бот, сохранить резервную копию,
мигрировать и запустить новый код. Push, deploy и такой переход сейчас не выполнялись.

Настройки окружения (пример имён есть в `.env.example`):

- `BOT_TOKEN` — прежний токен, не хранить в Git.
- `DB_PATH` — локально база разработки, на Amvera ожидается `/data/database.db`.
  Отсутствующая база не создаётся автоматически; проверьте путь и миграцию.
- `ALLOWED_TELEGRAM_IDS` — непустой список Telegram ID через запятую. Включить себя
  и друга явно. Неверный или пустой список останавливает запуск. Удалённые из
  списка пользователи не обслуживаются и не получают напоминания; данные сохраняются.
- `GOOGLE_SHEETS_OWNER_TELEGRAM_ID` — необязательный ID первоначального владельца
  истории. Должен совпасть с `schema_migrations.owner_telegram_id`. Без значения
  экспорт отключён для всех. Несовпадение также отключает экспорт.
- Google credentials — прежняя безопасная настройка окружения или файл в
  `credentials/`. Не помещать ключи в `.env.example`.

`.env` загружается до импорта слоя БД. Бот и Dispatcher создаются только внутри
`main()`, поэтому импорт модулей обработчиков не запускает polling.

## Как определяется пользователь

Telegram ID определяет аккаунт в Telegram; `users.id` — отдельный внутренний
ключ SQLite. Middleware сначала проверяет личный чат и список разрешённых ID,
после этого регистрирует пользователя или находит существующего. Старые данные
никогда не присваиваются новому пользователю: их владелец уже задан миграцией.
Первый личный контакт заполняет `private_chat_id` только для этого аккаунта.
После `/start` восстанавливаются его сохранённые задания уведомлений.

Обработчик получает доверенный `user_id` через механизм аргументов aiogram.
В кнопках нет полномочий на доступ: слой БД повторно проверяет владельца.
Внешние ключи запрещают несуществующих владельцев, но сами по себе не запрещают
чтение чужой записи — для этого нужны фильтры `WHERE user_id = ?` и JOIN workouts.

## Сохранённые сценарии и изменения поведения

- Каталог общий. A/B/C переносятся отдельной явной командой только владельцу;
  меню тренировок использует персональные программы SQLite. Конструктора пока нет.
- Подходы из одного сообщения сохраняются атомарно. История и подсказки весов
  выбираются только из собственных завершённых тренировок.
- Личные дневные показатели допускают одинаковую дату у разных людей.
  Дата опроса фиксируется при начале, чтобы переход через полночь не сменил запись.
- Новые времена тренировок включают смещение часового пояса пользователя.
  Старые времена не переписываются; наивные строки трактуются как местное время
  пользователя. По умолчанию это `Europe/Moscow`; UI выбора зоны пока нет.
- Один пользователь не может создать вторую незавершённую тренировку. Старые
  незавершённые записи миграция не удаляет; `/exit` сохраняет и завершает последнюю,
  `/cancel` явно удаляет её с подходами. Если старых активных записей несколько,
  команды обрабатывают их по одной, начиная с последней.
- Во время ввода нельзя начать другой опрос или редактирование расписания.
  `/start`, `/help`, `/today` и просмотр истории не сбрасывают тренировку.
  `/cancel` без тренировки отменяет текущий незавершённый опрос.
- Уведомление приглашает вызвать `/morning` или `/evening`; само состояние FSM
  не меняет. Задания имеют ID `morning:<users.id>` и `evening:<users.id>`.
  Расписание восстанавливается на старте и после `/start`, меняется персонально.
- Кнопки «отложить» и «завершить» содержат ID тренировки, индекс шага и ревизию
  SQLite. После перехода старая кнопка отклоняется. События одного пользователя
  обрабатываются последовательно через `SimpleEventIsolation`.
- В историю выводятся сохранённые названия упражнений, а не названия из текущего
  словаря программы; HTML в названиях экранируется.
- Sheets доступен только явно настроенному первоначальному владельцу. Другие
  пользователи не открывают Google-соединение. Чужой workout_id отклоняется до
  сети даже при вызове владельцем. Ошибка экспорта не отменяет сохранение SQLite;
  записывается общее предупреждение без credentials и текста исключения.

## Ограничения

- FSM хранится в памяти, но шаг и очередь новых тренировок сохраняются в SQLite.
  `/resume` восстанавливает их. Для старых тренировок без снимка остаются
  явные /exit и /cancel; программа не угадывается и не удаляется автоматически.
- Изоляция событий действует внутри одного процесса. Сохранить `singleton: true`.
- Google Sheets остаётся синхронным экспортом: медленный API задерживает обработку
  событий. Надёжной очереди повторных попыток пока нет; ошибки логируются.
  В колонке F листа Sets новые строки используют стабильный set_id, чтобы
  повторяющиеся упражнения не терялись. Старые строки поддерживаются.
- Для определения дня тренировки читаются собственные завершённые даты и
  преобразуются в Python: это корректно для смешанных старых/новых времён,
  но для большой истории понадобится оптимизация.
- Свежая пустая схема автоматически не создаётся. Используйте явно подготовленную
  БД v2; тесты строят старую схему и мигрируют её исключительно во временном каталоге.
- `import_workouts.py` больше не пишет при импорте модуля. Его ручной запуск требует
  `--database` и `--user-id` (внутренний ID), проверяет v1 и FK. Это административный
  импорт прежнего фиксированного списка, не пользовательский импорт программ.

## Проверки без сети

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
```

Временные базы создаются из замороженной старой схемы `tests/legacy_schema.py`.
Dispatcher-тесты используют настоящий роутинг и FSM aiogram с подставным транспортом
Telegram. Google-соединения заменены mocks; тесты проверяют отсутствие вызовов
авторизации для запрещённых сценариев. Реальный бот и Sheets не запускаются.
